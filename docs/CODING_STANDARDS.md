# Coding Standards

- Use strict TypeScript.
- Avoid `any`; isolate and document unavoidable third-party boundary cases.
- Prefer clear names and explicit units for scientific values.
- Keep modules cohesive and functions focused.
- Do not silence errors without explanation.
- Use comments for why, scientific assumptions, limitations, compatibility workarounds, and non-obvious performance decisions.
- Use ESLint and Prettier as the stable formatting and static analysis foundation.
- Do not edit `node_modules` or vendored third-party source.
